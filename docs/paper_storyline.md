## Problem

AI accelerator servers (Ascend 910A/910B) host bursty, phase-dependent, synchronization-sensitive memcpy traffic between host DDR and NPU HBM. Active probing of intra-host links (latency/bandwidth) is essential for monitoring and diagnosis, but traditional fixed-period probing overlaps with business memcpy bursts, causing resource contention, workload slowdown, and collective jitter. Threshold-triggered probing reduces unnecessary probes but still cannot determine *when* it is safe to probe.

The paper answers one question:

> How can we learn burst-gap patterns from Ascend intra-host memcpy traffic and predict safe probing windows to reduce probe interference to AI workloads?

---

## Insight

Ascend memcpy traffic is bursty but not random. For a given workload, recent event history, iteration phase, stream behavior, path, and synchronization events provide enough information to conservatively predict whether a future horizon is safe for probing. The system does not need to precisely reconstruct all traffic — it only needs to conservatively answer: "Is this path likely to be idle long enough for a probe?"

This shifts active probing from:

```
periodic probing / threshold-triggered probing
```

to:

```
confidence-calibrated safe-window probing
```

## System

FlowGap is a probing opportunity inference layer with three modules:

```text
eBPF collects memcpy/sync events
    ↓
Event normalizer resolves src/dst/path/link
    ↓
Busy-idle timeline builder constructs path/link intervals
    ↓
Multi-horizon survival predictor estimates safe windows
    ↓
Confidence calibrator corrects model confidence
    ↓
Prober executes/downgrades/cancels probe
    ↓
Analyzer evaluates probe result and feeds back overlap/duration/error
```

### Predictor (core contribution)
- Collect AscendCL memcpy/sync events with eBPF uprobes.
- Normalize events into path/link busy-idle timelines using probe-aware intervalization (merge gaps shorter than minimum probe time).
- Maintain conservative timeline (for safety decisions) and estimated timeline (for model learning) to handle async memcpy uncertainty.
- Use multi-horizon survival predictor: P(T_next > h | x_t) for h ∈ {10μs, 25μs, 50μs, 100μs, 250μs, 500μs, 1ms, 2ms}.
- Calibrate confidence with four components: model probability, empirical calibration, data quality, drift detection.
- Publish SafeWindow only when G_lower > T_probe + margin AND confidence > eta.

### Prober
- Select probe type based on confidence tier: bandwidth (C > 0.98) → normal latency (0.95-0.98) → tiny latency (0.90-0.95) → no probe (≤ 0.90).
- Cancel or downgrade probes when predicted window becomes unsafe.
- Enforce probe budget.

### Analyzer
- Assess probe result trustworthiness (overlap detection).
- Feed actual overlap, probe duration, and prediction error back to predictor for online calibration.
- Support failure-aware probing mode for detection scenarios.

## Cloud Systems Relevance

FlowGap is positioned as a cloud / AI-infrastructure monitoring system:

- AI training/serving clusters increasingly depend on accelerator servers (Ascend 910A/910B, NVIDIA GPUs).
- Active probing is essential for intra-host bottleneck diagnosis.
- But probing can perturb the very workloads being diagnosed — especially bursty, sync-sensitive AI computation.
- FlowGap reduces measurement-induced interference through safe-window prediction, connecting tracing, monitoring, scheduling, and reliability for ML training/serving.

This is NOT:
- A pure time-series forecasting paper;
- A complete root-cause diagnosis system;
- A hardware-specific engineering note without broader cloud systems relevance.

## Key Difference from Hostping/HostDiag

| Aspect | Hostping | HostDiag | FlowGap |
|---|---|---|---|
| Target platform | RDMA/RNIC servers | Heterogeneous accelerator servers | Ascend 910A/910B |
| Core mechanism | Loopback latency/bandwidth test | eBPF-hooked memcpy probing | eBPF-hooked safe-window prediction + probing |
| Probe timing | Hardware state / abnormality trigger | DML throughput threshold | Predicted safe windows from burst-gap patterns |
| Main contribution | Proving intra-host probing value | Extending probing to AI accelerators | Deciding *when* to probe safely |
| Relationship | Baseline awareness | Inherits eBPF hook approach | Adds prediction layer for timing decision |

FlowGap does not replace Hostping/HostDiag — it adds a probing opportunity inference layer that can be used *before* the probing step in any host-side diagnosis system.
