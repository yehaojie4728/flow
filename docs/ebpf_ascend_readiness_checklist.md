## Legend

- **[ ]** = not yet checked
- **PASS** = meets requirement
- **WARN** = works but with caveats (e.g., optional feature missing, fallback available)
- **FAIL** = blocker — must be resolved before FlowGap development can proceed on this machine

## Blockers (any FAIL = BLOCKED)

1. libascendcl.so not found or stripped
2. aclrtMemcpy symbol not visible
3. Architecture not aarch64
4. No kernel headers for BPF compilation
5. perf_event_paranoid > 2 without root
6. bpfcc not importable
7. g++ not available

## Notes

- If `aclrtMemcpyAsync` symbols are missing, FlowGap's async module cannot be tested but sync-mode predictor can still proceed.
- If `aclrtMemcpy2d` symbols are missing, 2D memcpy hooks can be deferred to a later patch.
- If aeon is not installed, substitute with statsmodels for time-series baselines.
- **Conda + bpfcc known issue:** yum-installed `python3-bpfcc` is installed for system Python (`/usr/bin/python3`), not for conda's `python3`. Solution: use `/usr/bin/python3` for collector scripts, or set `PYTHONPATH` to include system site-packages. The updated `check_flowgap_env.sh` detects this and reports WARN instead of FAIL.
- `kernel.unprivileged_bpf_disabled=2` is expected on Ascend servers and does NOT block root-level eBPF usage.
