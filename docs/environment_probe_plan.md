# FlowGap Environment Probe Plan

Generated by `docs/prompts/02_codex_environment_probe_plan.md`.
Target machine: Ascend 910A aarch64 EulerOS / openEuler.

---

## Goal

Determine whether the target Ascend machine is ready for FlowGap development, specifically:

1. Whether eBPF (bpfcc) can attach uprobes to AscendCL `libascendcl.so`.
2. Whether the CANN/AscendCL SDK has the required APIs with usable symbol names.
3. Whether the machine has the topology information needed for path/link mapping.
4. Whether Python and build tools are available.

---

## What this plan does NOT do

- Does NOT install packages.
- Does NOT modify kernel settings.
- Does NOT load/unload kernel modules.
- Does NOT attach uprobes to any process.
- Does NOT start any daemon.
- Does NOT write to system directories.
- Does NOT mount filesystems.

Everything is read-only: `uname`, `cat`, `find`, `ls`, `nm`, `grep`, `stat`, `python3 -c`, etc.

## Expected outcomes

### GREEN (expected on target machine)

| Category | Expected |
|---|---|
| OS | EulerOS / openEuler, kernel >= 4.19, aarch64 |
| Kernel config | CONFIG_BPF=y, CONFIG_BPF_SYSCALL=y, CONFIG_UPROBES=y, CONFIG_PERF_EVENTS=y, BTF=y |
| BCC | bpfcc Python package installed and importable |
| CANN | CANN installed, libascendcl.so is an aarch64 ELF with unmangled C symbols |
| Symbols | aclrtMemcpy, aclrtSetDevice, aclrtMemcpyAsync visible in nm -D |
| Python | >= 3.8, numpy/scikit-learn/pandas available |
| Build | g++ >= 8, libnuma-dev installed |
| Permissions | root user, or CAP_BPF + CAP_SYS_ADMIN |
| perf_event_paranoid | <= 2 |

### YELLOW (warnings — workable with fallback)

| Category | Warning |
|---|---|
| BTF | Missing BTF means bpfcc will fall back to /proc/kallsyms |
| Async symbols | aclrtMemcpyAsync may have a different name or be mangled |
| 2d symbols | aclrtMemcpy2d may not be present; FlowGap can start with 1d only |
| Python ML | Some packages missing; can install later |
| Conda + bpfcc | yum-installed `python3-bpfcc` may not be visible to conda `python3`. Use `/usr/bin/python3` for eBPF scripts, or set `PYTHONPATH` to include system site-packages. |

### RED (blockers — must be resolved before development)

| Category | Blocker |
|---|---|
| OS arch | Not aarch64 → Ascend SDK won't work |
| libascendcl.so | Not found → CANN not installed |
| Symbols stripped | libascendcl.so is stripped → uprobe won't work |
| No kernel headers | Can't compile BPF programs |
| perf_event_paranoid | > 2 without root → can't use BPF perf output |
| bpfcc not installed | Can't load BPF programs |

## Execution instructions

1. Copy `scripts/check_flowgap_env.sh` to the target Ascend machine.
2. Run without root first: `bash scripts/check_flowgap_env.sh` — this covers Python, build tools, library paths.
3. Run with root/sudo: `sudo bash scripts/check_flowgap_env.sh` — this covers kernel config, debugfs, BPF readiness.
4. Review output. RED items must be fixed before development. YELLOW items are informative.
5. If libascendcl.so is found with valid symbols, the machine is ready for Patch 1 (eBPF hooks).

## Relation to HostDiagV2 readiness

HostDiagV2's `trace_memcpy_numa.py` was already run on an Ascend 910B2 machine (as evidenced by real trace data in `external/reference_repo/runs/`). This means:

- The same bpfcc + uprobe pattern works on Ascend.
- The same `libascendcl.so` path resolution logic works.
- The same `aclrtMemcpy` and `aclrtSetDevice` symbols exist.

The environment probe validates that the *current* FlowGap target machine has the same readiness state, and additionally checks for symbols that HostDiagV2 did not use (`aclrtMemcpyAsync`, `aclrtSynchronizeStream`, `aclrtMallocHost`, `aclrtMallocDevice`).
