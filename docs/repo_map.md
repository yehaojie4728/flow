## Search results per target category

### 1. eBPF / bpfcc / libbpf / uprobe code

**FOUND** in `src/trace_memcpy_numa.py`:
- Uses `from bpfcc import BPF` (BCC Python wrapper).
- Hooks: `aclrtSetDevice` (uprobe), `aclrtMemcpy` (uprobe + uretprobe).
- BPF program: inline C code (150 lines) with `BPF_HASH(start_map)`, `BPF_HASH(thread_device)`, `BPF_PERF_OUTPUT(events)`.
- Library resolution: searches env vars + canonical paths for `libascendcl.so`.
- No kprobe, tracepoint, or libbpf CO-RE usage.

### 3. Prober code

**FOUND** in `probe/src/memcpy_benchmark.cpp`:
- SIGUSR1-triggered single-link probing.
- Sequence: Bandwidth (128MB) → Latency (4KB × 10 iterations).
- Direction: H2D or D2H, determined from daemon's request CSV.
- NUMA binding via `set_mempolicy(MPOL_BIND)`.
- Baselines: 26.5 GB/s (same NUMA), 21.9 GB/s (cross NUMA).
- Latency threshold: 35 µs.
- Output: human-readable report with fault analysis per loop.
- State management: writes `idle`/`busy` to `probe.status`.
- NOT found: probe type selection, downgrade, cancellation, budget enforcement, confidence-gated admission.

### 4. Analyzer code

**FOUND** in 3 files:
- `src/probe_severity_analyzer.py`: Parses probe.log for fault blocks, matches probes to agg windows, computes throughput ratio against fixed baseline (25 GB/s), assigns P0/P1/P2 severity with confidence scores (90/65/30).
- `src/probe_analysis_worker.py`: Stat-polling worker that runs analyzer on file change.
- `src/export_uploader_topo.py`: Maps severity results to platform topology JSON for upload.

NOT found: overlap detection, feedback loop to predictor, anomaly detection beyond fixed-baseline comparison, failure-aware probing.

### 5. Trace/log schema

**FOUND** — 3 distinct schemas:

**Raw trace** (`runs/raw/aclrtMemcpy_numa_raw.log`):
```
PID,TID,Source,Destination,Size_MB,Latency_us,Bandwidth_GBps,Start_ns,End_ns,WallStart_ns,WallEnd_ns
```
Source = `Host(NUMA N)` or `NPU N`. Destination similarly. Device `?` when device context tracking missed.

**Aggregated trace** (`runs/agg/aclrtMemcpy_numa_trace.log`):
```
WindowStart_ns,WindowEnd_ns,Source,Destination,Bytes_MB,Bandwidth_GBps,WindowStartWall_ns,WindowEndWall_ns,Duration_ms,Packet_Count
```
Note: aggregation is `src→dst` with overlapping interval merge, NOT fixed time bins.

**Probe request** (`logs/runtime/probe_request.csv`):
```
request_id,trigger_wall_ns,source,destination,direction,device_id,numa_id,window_start_ns,window_end_ns,window_bw_gbps
```

### 6. Build scripts

**FOUND:**
- `probe/CMakeLists.txt`: cmake for probe (arch: gnu++11, links ascendcl + pthread + numa).
- `probe/build.sh`: fallback direct g++ build.
- `scripts/start_monitor_stack.sh`: g++ -O2 compile of daemon at startup, resolves probe binary from multiple candidates.
- No Makefile, no setup.py, no pyproject.toml, no requirements.txt. Python dependencies implicit (bpfcc, standard library only).

### 7. Risky code

**IDENTIFIED:**
- `trace_memcpy_numa.py`: Reads `/proc/*/task/*/stat` at runtime (privacy risk in shared environments).
- `trace_memcpy_numa.py`: Requires root/CAP_BPF for eBPF uprobe attachment.
- `npu_adaptive_daemon.cpp`: Reads `/proc/*/cmdline` to find probe PID (non-standard PID discovery).
- `memcpy_benchmark.cpp`: Uses `set_mempolicy(MPOL_BIND)` (NUMA memory binding, root or CAP_SYS_NICE).
- `memcpy_benchmark.cpp`: Calls `popen("npu-smi info -t topo")` (runs external binary).
- `scripts/start_monitor_stack.sh`: Uses `pkill -f` globally (may kill unrelated processes).
