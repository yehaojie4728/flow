## Tier 1: Directly Reusable (copy with minimal changes)

These components solve problems that FlowGap also needs, with no conflicting design choices.

### 1.1 eBPF Hook Code (`trace_memcpy_numa.py` lines ~120-260 — BPF C program)

**What to reuse:**
- Inline BPF C program for `aclrtMemcpy` uprobe/uretprobe.
- `struct start_t` and `struct data_t` definitions.
- `BPF_HASH(start_map)` and `BPF_HASH(thread_device)` patterns.
- `BPF_PERF_OUTPUT(events)` ring buffer setup.
- Event fields: `pid`, `tid`, `ts`, `dst`, `destMax`, `src`, `count`, `kind`, `delta`, `current_device`.

**Changes needed:**
- Add `path_id` and `link_bitmap` fields (computed in user-space, not BPF).
- Add `quality_flags` field.
- Add `min_size` threshold parameterization (already supported via printf-style formatting).

**Target file in FlowGap:** `src/collector/ebpf_hooks/memcpy_hook.c` (extracted from inline Python string).

### 1.2 Probe Execution Code (`probe/src/memcpy_benchmark.cpp` lines ~290-430)

**What to reuse:**
- `measure_bandwidth()` and `measure_latency()` functions.
- `prepare_buffers()` and `release_buffers()` functions.
- `read_cntvct()` / `read_cntfrq()` / `ticks_to_us()` timing infrastructure.
- `ProbeMetric` struct.
- ACL lifecycle: `aclrtSetCurrentContext`, `aclrtSynchronizeDevice`.
- NUMA binding: `set_mempolicy(MPOL_BIND)`.

**Changes needed:**
- Extract into reusable C++ class/library (not monolithic main).
- Add configurable probe parameters (bandwidth bytes, latency bytes, iters).
- Add `run_one_copy()` with configurable direction and size.
- Remove SIGUSR1 handler (replaced by scheduler).
- Remove fault analysis output (replaced by structured analyzer output).

**Target file in FlowGap:** `src/prober/probe_executor.cpp`

### 1.3 Topology Detection (`probe/src/memcpy_benchmark.cpp` lines ~130-195)

**What to reuse:**
- `init_topology_910b()` and `init_topology_910a()` with NPU↔CPU/NUMA mappings.
- `detect_soc_and_init_topology()` using `aclrtGetSocName()`.
- `check_hccs_topology()` using `npu-smi info -t topo`.
- `is_same_numa_group()` function.

**Changes needed:**
- Extract into separate topology module.
- Add topology to data structures accessible by normalizer and predictor.

**Target file in FlowGap:** `src/normalizer/topo.py` (Python port) and `src/normalizer/topo_detect.cpp` (C++).

## Tier 2: Adaptable (copy and substantially modify)

### 2.1 eBPF Library Resolution + BPF loader (`trace_memcpy_numa.py` lines ~30-110)

**What to adapt:**
- `resolve_ascendcl_lib()` function — searches env vars + canonical paths.
- `resolve_bpf_cflags()` — aarch64 target detection.
- `b.attach_uprobe()` / `b.attach_uretprobe()` calls.
- CPU→NUMA mapping from `/sys/devices/system/cpu`.

**Changes needed:**
- Add hooks for additional APIs: `aclrtMemcpyAsync`, `aclrtSynchronizeStream`, `aclrtMallocHost`, `aclrtMallocDevice`, `aclrtFreeHost`, `aclrtFree`.
- Add `aclrtSetDevice` hook for device context tracking (already present, keep).
- Replace `/proc/pid/task/tid/stat` parsing with BPF-based CPU→NUMA inference.
- Add `aclrtMallocHost`/`aclrtMallocDevice` hooks for address→device mapping.
- Structure hooks into separate Python modules (not monolith).
- Add structured error handling and BPF program verification.

**Target files in FlowGap:**
- `src/collector/ebpf_hooks/memcpy_hook.c` (sync + async entry/return)
- `src/collector/ebpf_hooks/stream_hook.c` (stream sync)
- `src/collector/ebpf_hooks/alloc_hook.c` (malloc/free)
- `src/collector/lib_resolver.py`
- `src/collector/bpf_loader.py`

### 2.2 Event Normalization (`trace_memcpy_numa.py` lines ~320-400)

**What to adapt:**
- Source/Destination string construction from `kind` + NUMA + device.
- NUMA resolution via `/proc` (or adapt to BPF-based).
- `merge_or_flush_window()` for busy interval merging.

**Changes needed:**
- Replace string-based Source/Destination with structured `path_id` + `link_bitmap`.
- Add address→device mapping from malloc hooks.
- Replace overlap-based merging with probe-aware intervalization (merge gaps < T_probe_min + M).
- Maintain per-path and per-link interval trees, not just per-src→dst.
- Add direction and stream metadata.
- Add quality_flags assignment (drop, unknown_path, async_uncertainty, timestamp_jitter).

**Target file in FlowGap:** Rewrite as `src/normalizer/event_normalizer.py`

### 2.3 Probe Execution Framework (`probe/build.sh`, `probe/CMakeLists.txt`)

**What to adapt:**
- Library resolution logic (cann-8.5.0 pattern).
- Link flags: `-lascendcl -lpthread -lnuma`.
- Include directory search pattern.

**Changes needed:**
- Support multiple CANN versions (not just 8.5.0).
- Add FlowGap's own source files.
- Add Python package build (setup.py or pyproject.toml).
- Add eBPF compilation step.

**Target files in FlowGap:**
- `prober/CMakeLists.txt`
- `pyproject.toml` or `setup.py`

### 2.4 Trace Schema

**What to adapt:**
- Raw trace CSV format (11 columns).
- Aggregated trace CSV format (10 columns).

**Changes needed:**
- Define FlowEvent binary format (from `docs/outline.md` §4.1.2) — this replaces CSV for runtime.
- Keep CSV export for offline analysis/debugging.
- Add per-event fields: `path_id`, `link_bitmap`, `async_flag`, `api_type`, `quality_flags`, `stream_id`.
- Add per-window fields for probe-aware aggregation.

**Target file in FlowGap:** `docs/collector_schema.md`

## Tier 3: Reference Only (understand, then reimplement fresh)

### 3.1 Daemon (`npu_adaptive_daemon.cpp`)

**Reference value:** Shows how to read from agg trace, parse CSV, and write probe requests.

**Why reimplement:** The daemon's core logic (threshold-based triggering) is exactly what FlowGap replaces. However, its IPC patterns (PID file, status file, SIGUSR1, CSV request file) may inform the prober scheduler's interface.

### 3.2 Severity Analyzer (`probe_severity_analyzer.py`)

**Reference value:** Shows how to parse probe.log, extract fault analysis blocks, and match probes to agg windows.

**Why reimplement:** The severity logic (P0/P1/P2 based on fixed baseline) is not part of FlowGap's core contribution. FlowGap needs a feedback analyzer, not a severity classifier. The parsing patterns are useful reference.

### 3.3 Uploader Export (`export_uploader_topo.py`)

**Reference value:** Shows topology mapping between internal link representation and external platform schema.

**Why reimplement:** Not directly relevant to FlowGap's novel contribution. Only needed if evaluation requires integration testing.

### 3.4 Shell Scripts (`scripts/start_monitor_stack.sh`, `scripts/stop_monitor_stack.sh`)

**Reference value:** Shows process lifecycle management.

**Why reimplement:** FlowGap has a different process model (predictor daemon + prober + analyzer, not daemon + standalone probe). Integration test scripts should be written fresh.

### 3.5 Build System

**Reference value:** Shows CANN include/lib paths, compiler flags.

**Why reimplement:** FlowGap has more components (Python predictor, eBPF hooks, C++ prober). Needs a proper build system.

## Tier 4: Must Build from Scratch (core FlowGap novelty)

These components have no precedent in the reference repo:

| Component | Reason no reuse possible |
|---|---|
| Async memcpy hooks (async entry, stream sync, 2d variants) | HostDiagV2 only hooks sync `aclrtMemcpy` |
| Probe-aware busy-idle intervalization | HostDiagV2 uses overlap merging, not micro-gap merging |
| Async interval estimator (conservative + estimated timelines) | No async handling in HostDiagV2 |
| Multi-horizon survival predictor | Core novel contribution |
| Feature extraction pipeline | Needed for prediction; no precedent |
| Gap lower-bound estimator | No precedent |
| Confidence calibrator (model + empirical + data_quality + drift) | HostDiagV2 has fixed confidence mapping only |
| Probe admission control + downgrade + cancellation | HostDiagV2 has SIGUSR1 + cooldown only |
| Structured feedback loop to predictor | HostDiagV2 has human-readable text logs only |
| Synthetic workload generator | No precedent |
| Evaluation framework (RQ1-RQ8) | No precedent |

## Reuse Dependency Graph

```text
Tier 1 (direct):    eBPF hook code ──┬──→ src/collector/ebpf_hooks/
                    probe executor ──┼──→ src/prober/probe_executor.cpp
                    topology detect ──┘

Tier 2 (adapt):     lib resolver  ────→ src/collector/lib_resolver.py
                    bpf loader ───────→ src/collector/bpf_loader.py
                    event normalizer ──→ src/normalizer/event_normalizer.py
                    trace schema  ─────→ docs/collector_schema.md

Tier 3 (reference): daemon ──────────→ (informs scheduler interface)
                    severity analyzer → (informs feedback analyzer)
                    shell scripts ────→ (informs integration tests)

Tier 4 (from scratch): async hooks, predictor, calibrator, scheduler, analyzer, evaluation
```

## Implementation Order

1. **First:** Extract Tier 1 components into FlowGap (eBPF hook code, probe executor, topology) — gives working data collection.
2. **Second:** Adapt Tier 2 components (extend eBPF hooks for async, build normalizer, define FlowEvent schema) — provides clean data pipeline.
3. **Third:** Build Tier 4 components in order: predictor → calibrator → scheduler → analyzer.
4. **Parallel:** Build synthetic workload generator and evaluation framework while predictor is being developed.
