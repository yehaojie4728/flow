## Purpose

Evaluate FlowGap probe placement policies **offline** against real Ascend 910B trace data, without requiring live hardware. Enables rapid policy comparison and hyperparameter tuning before connecting the live probe executor.

## Policy design

### 1. no_probing

Zero probes. Establishes the overhead baseline (0%).

### 2. fixed_interval

One tiny latency probe every K ms. Simplest naive strategy — shows what happens with no adaptation.

### 3. random

Flip a biased coin on each gap. Illustrates the cost of blind probing.

### 4. threshold

Probe only when gap exceeds given bandwidth threshold (500 µs for normal latency, 5 ms for bandwidth). Naive adaptation based on gap size alone.

### 5. ewma_only

Uses the `EWMBaseline` from `code/gap_predictor/` (Tier 0). Predicts P(gap ≥ h) from exponential-weighted moving average of recent gap durations. Requires warmup of 10 gaps per path.

### 6. flowgap_predictive

Full GBDT survival predictor from `code/gap_predictor/` (Tier 1). Loads trained model, extracts 30-dimensional feature vector, predicts per-horizon safety probabilities. Falls back to EWMA if model unavailable.

### 7. oracle

Upper bound — knows all future gap durations. Probes only when the actual gap can accommodate the probe. Never produces unsafe probes by definition.

## Replay algorithm

```
for each gap, chronologically:
    1. Get policy decision for this gap
    2. Check probe latency against gap duration
    3. Downgrade probe type if gap too small
    4. Check overlap with active probes on this path
    5. Compute overlap with busy intervals
    6. Record ProbeOutcome
```

## Metrics computed

| Metric | Definition |
|---|---|
| `safe_probing_ratio` | safe_probes / executed_probes |
| `probe_overlap_ratio` | ns_overlapping / total_probe_ns |
| `harmful_probe_count` | probes with any overlap |
| `probing_overhead_pct` | total_probe_ns / total_trace_ns × 100 |
| Per-path breakdown | safe/unsafe/executed per path_id |
