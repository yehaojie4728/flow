## Executive Summary

The reference repo (`external/reference_repo/`) contains **HostDiagV2** — a working intra-host link diagnosis system for Ascend 910A/B, with real trace data. The system integrates eBPF monitoring, threshold-triggered probing, and severity analysis. This provides substantial reusable code and real data for FlowGap.

---

## System Architecture

```
eBPF monitor (trace_memcpy_numa.py)
    ↓  raw csv + agg csv
Daemon (npu_adaptive_daemon.cpp)
    ↓  SIGUSR1 + probe_request.csv
Probe (memcpy_benchmark.cpp)
    ↓  probe.log
Analyzer Worker (probe_analysis_worker.py)
    ↓  reads probe.log + agg trace
Severity Analyzer (probe_severity_analyzer.py)
    ↓  probe_severity.csv
Uploader Export (export_uploader_topo.py)
    ↓  probe_topo_payload.json
```

### Key characteristics

- **Probe timing is threshold-triggered, NOT predictive.** The daemon triggers when throughput falls in an "abnormal range" (`low_mbps < rate < high_mbps`). Default: 800-26000 MB/s. This is reactive — it fires *after* an anomaly is observed, not predictively.
- **Single-link probing only.** No matrix probing, no warmup, no bidirectional. Bandwidth (128MB) then latency (4KB×10).
- **No async handling.** Only `aclrtMemcpy` (sync) is hooked. `aclrtMemcpyAsync` is NOT monitored.
- **No confidence calibration.** The "confidence" in severity output (90/65/30) is a fixed mapping from severity level to confidence, not data-driven calibration.
- **Cooldown-based scheduling.** Redundant triggers are suppressed by a 10-second cooldown, not by gap prediction.

## Trace Data Quality

### Available real traces

The repo contains **real trace data** from an Ascend 910B2 server:

- Raw trace: 29 lines of `aclrtMemcpy` events from a multi-threaded workload.
- Aggregated trace: 29 aggregated windows.
- Probe logs: 2 probe loops with bandwidth/latency reports.
- Probe severity: 2 severity assessments.

### Trace characteristics (from sample)

| Metric | Observed values |
|---|---|
| Copy sizes | 24.5 MB, 31.5 MB, 128 MB, 129.5 MB, 259 MB |
| Bandwidth range | 5.72 - 16.65 GB/s |
| Latency range | 2400 - 39834 µs |
| Paths observed | Host(NUMA 0)→NPU 2, Host(NUMA 1)→NPU 2/3, Host(NUMA 2)→NPU 2/4, Host(NUMA 0)→NPU 5 |
| Directions | All H2D (kind=1) in sample |
| Threads | 4 threads (2771269, 2771270, 2771271, 2771272) |
| Multi-NUMA | NUMA 0, 1, 2 observed |
| Device tracking gap | One event shows `Device ?` (device context was not tracked for thread 2770322) |

### Data quality issues

1. **Device `?` entries:** About 3.4% of events (1/29) have unknown device. Caused by threads that never called `aclrtSetDevice` while the eBPF program was attached.
2. **No async traces:** Only synchronous `aclrtMemcpy` in sample. Real AI workloads extensively use `aclrtMemcpyAsync`.
3. **No D2H/D2D traffic:** Sample contains only H2D. D2H and D2D traffic patterns are not represented.
4. **No aggregation merging:** The "aggregated" trace actually shows Packet_Count=1 for all rows — no interval merging is occurring because the default 100ms window and this specific traffic pattern produce non-overlapping intervals.
5. **Limited trace length:** 29 events is insufficient for characterizing burst-gap patterns or training a predictor.

## Key Architecture Differences: HostDiagV2 vs FlowGap

| Aspect | HostDiagV2 | FlowGap |
|---|---|---|
| Probe timing | Reactive: trigger on abnormal throughput | Predictive: trigger on predicted safe window |
| Trigger signal | `low < rate_mbps < high` (rate-based threshold) | `G_lower > T_probe + margin AND confidence > eta` |
| Event hooks | `aclrtSetDevice` + `aclrtMemcpy` (sync only) | Same + `aclrtMemcpyAsync`, `aclrtSynchronizeStream`, `aclrtMemcpy2d*`, `aclrtMalloc*` |
| Timeline | Event-driven with overlap merge | Probe-aware intervalization with micro-gap merging |
| Path tracking | `Source/Destination` as `Host(NUMA N)` or `NPU N` | `path_id` + `link_bitmap` |
| Async handling | None | Conservative + estimated timelines |
| Confidence | Fixed mapping (P0→90, P1→65, P2→30) | Calibrated: model + empirical + data_quality + drift |
| Probe types | Bandwidth (128MB) then Latency (4KB×10) | Tiered: bandwidth/normal_latency/tiny_latency based on confidence |
| Scheduling | Cooldown-based (10 sec) | Confidence-gated admission + downgrade + cancellation |
| Analyzer feedback | Human-readable text logs | Structured feedback to predictor |
| Evaluation | Severity classification (P0/P1/P2) | RQ1-RQ8: prediction, scheduling, interference, detection, robustness |
