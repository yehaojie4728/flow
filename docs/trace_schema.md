## 1. FlowEvent (Binary Runtime Format)

This is the internal wire format carried over the eBPF ring buffer / perf buffer. Extended from HostDiagV2's `data_t`.

### 1.1 Layout

```c
struct FlowEvent {
    u64 ts_enter_ns;       // BPF ktime_get_ns() at aclrtMemcpy entry
    u64 ts_exit_ns;        // BPF ktime_get_ns() at aclrtMemcpy return  (= ts_enter_ns + delta)
    u64 ts_submit_ns;      // for async: user-space estimated submit time; for sync: = ts_enter_ns
    u64 ts_end_est_ns;     // for async: estimated completion time; for sync: = ts_exit_ns

    u64 ts_wall_ns;        // wall clock at event emission (user-space fills this)

    u32 pid;
    u32 tid;
    u64 stream_id;         // 0 for sync calls

    u32 src_dev;           // NPU id, or HOST_DEVICE_ID (0xFFFFFFFF) for host
    u32 dst_dev;
    u32 src_numa;          // NUMA node, or UNKNOWN_NUMA (0xFF)
    u32 dst_numa;

    u64 size;              // bytes
    u8  direction;         // 0=H2H, 1=H2D, 2=D2H, 3=D2D
    u8  async_flag;        // 0=sync, 1=async
    u8  api_type;          // 0=memcpy, 1=memcpyAsync, 2=memcpy2d, 3=memcpy2dAsync, 4=streamSync

    u16 path_id;           // computed by normalizer
    u64 link_bitmap;       // bitmask of logical links on this path

    u32 quality_flags;     // bit field (see below)

    u32 padding;           // align to 64 bytes
} __attribute__((packed));   // total: 88 bytes
```

### 1.2 Constants

```c
#define HOST_DEVICE_ID    0xFFFFFFFF
#define UNKNOWN_NUMA      0xFF
#define UNKNOWN_DEVICE    0xFFFFFFFE

#define DIR_H2H  0
#define DIR_H2D  1
#define DIR_D2H  2
#define DIR_D2D  3

#define API_MEMCPY       0
#define API_MEMCPY_ASYNC 1
#define API_MEMCPY_2D    2
#define API_MEMCPY_2D_ASYNC 3
#define API_STREAM_SYNC  4
#define API_SET_DEVICE   5   // device context change (no memcpy)
#define API_MALLOC_HOST  6
#define API_MALLOC_DEVICE 7
#define API_FREE_HOST    8
#define API_FREE_DEVICE  9
```

### 1.3 Quality flags (bit field)

```c
#define QF_UNKNOWN_PATH       (1 << 0)   // path resolution failed
#define QF_UNKNOWN_DEVICE     (1 << 1)   // device context unknown (Device ?  in HostDiagV2)
#define QF_ASYNC_UNCERTAINTY  (1 << 2)   // async completion time estimated, not measured
#define QF_TIMESTAMP_JITTER   (1 << 3)   // wall clock vs monotonic delta > threshold
#define QF_ADDRESS_UNMAPPED   (1 << 4)   // src or dst address not in alloc map
#define QF_RING_DROP          (1 << 5)   // ring buffer was near overflow
#define QF_MERGED_GAP         (1 << 6)   // this event's gap was merged (probe-aware intervalization)
#define QF_SYNTHETIC          (1 << 7)   // synthetic event, not from real trace
```

## 2. Raw Trace CSV (Offline / Debug Format)

Extended from HostDiagV2's 11-column raw log. Used for offline analysis, sharing, and synthetic trace generation.

```csv
pid,tid,src_dev,dst_dev,src_numa,dst_numa,size_mb,latency_us,bw_gbps,start_ns,end_ns,wall_start_ns,wall_end_ns,direction,async_flag,api_type,stream_id,path_id,link_bitmap,quality_flags
```

### 2.1 Column definitions

| Column | Type | Description |
|---|---|---|
| pid | u32 | Process ID |
| tid | u32 | Thread ID |
| src_dev | u32 | Source NPU id, or HOST_DEVICE_ID |
| dst_dev | u32 | Destination NPU id |
| src_numa | u32 | Source NUMA node |
| dst_numa | u32 | Destination NUMA node |
| size_mb | f64 | Size in MB |
| latency_us | f64 | Duration in µs |
| bw_gbps | f64 | Effective bandwidth in GB/s |
| start_ns | u64 | Start timestamp (monotonic ns) |
| end_ns | u64 | End timestamp (monotonic ns) |
| wall_start_ns | u64 | Wall clock at event start |
| wall_end_ns | u64 | Wall clock at event end |
| direction | u8 | 0=H2H, 1=H2D, 2=D2H, 3=D2D |
| async_flag | u8 | 0=sync, 1=async |
| api_type | u8 | API type code |
| stream_id | u64 | Stream ID (0 for sync) |
| path_id | u16 | Normalizer-computed path ID |
| link_bitmap | u64 | Link bitmask |
| quality_flags | u32 | Quality flags |

### 2.2 Source/Destination naming convention

In the original HostDiagV2, Source and Destination were strings: `Host(NUMA 0)` or `NPU 2`. FlowGap replaces these with structured numeric fields (`src_dev`, `dst_dev`, `src_numa`, `dst_numa`) for deterministic computation. A human-readable form is derived from these fields for logging:

- `Host(NUMA N)` → `src_dev=HOST_DEVICE_ID, src_numa=N`
- `NPU N` → `dst_dev=N, dst_numa=UNKNOWN_NUMA`

## 3. Aggregated Trace CSV (Offline Format)

Same structure as HostDiagV2's agg trace, extended with path-level columns.

```csv
window_start_ns,window_end_ns,src_dev,dst_dev,src_numa,dst_numa,path_id,link_bitmap,bytes_mb,bw_gbps,wall_start_ns,wall_end_ns,duration_ms,packet_count,direction
```

| Column | Type | Description |
|---|---|---|
| window_start_ns | u64 | Aggregated window start (monotonic) |
| window_end_ns | u64 | Aggregated window end (monotonic) |
| src_dev | u32 | Source NPU or HOST |
| dst_dev | u32 | Destination NPU |
| src_numa | u32 | Source NUMA |
| dst_numa | u32 | Destination NUMA |
| path_id | u16 | Unique path identifier |
| link_bitmap | u64 | Logical link bitmask |
| bytes_mb | f64 | Total bytes in window |
| bw_gbps | f64 | Effective bandwidth |
| wall_start_ns | u64 | Wall clock start |
| wall_end_ns | u64 | Wall clock end |
| duration_ms | f64 | Window duration in ms |
| packet_count | u32 | Number of merged events |
| direction | u8 | H2D / D2H / D2D |

### 3.1 Note on aggregation method

FlowGap replaces HostDiagV2's simple overlap-based merging with **probe-aware intervalization**:
- Adjacent busy intervals are merged if the gap between them is less than `T_probe_min + safety_margin`.
- This means a single agg window may span multiple original events if micro-gaps exist.
- The `packet_count` field records how many raw events were merged.
- Intervals separated by gaps >= `T_probe_min + safety_margin` remain separate (these are potential safe windows).

## 4. SafeWindow Publication Format

Output from predictor to prober scheduler. Not a file format — this is an in-memory struct published over a queue / shared memory channel.

```python
@dataclass
class SafeWindow:
    path_id: int
    link_bitmap: int
    t_publish: int          # monotonic ns when this window was computed
    t_valid_from: int       # monotonic ns from which the prediction is valid
    g_lower_bound: int      # predicted conservative gap lower bound (ns)
    p_safe: float           # predicted safe probability S(h | x_t)
    confidence: float       # calibrated confidence C_final
    horizon_ns: int         # the horizon h this prediction is valid for
    allowed_probe_type: int # 0=none, 1=tiny_latency, 2=normal_latency, 3=bandwidth
    max_probe_size: int     # max bytes for probe at this confidence
    reason_code: int        # why this window was or was not published
```

### 4.1 Probe type codes

```python
PROBE_TYPE_NONE          = 0   # do not probe
PROBE_TYPE_TINY_LATENCY  = 1   # very small, quick (e.g. 4KB × 1)
PROBE_TYPE_NORMAL_LATENCY = 2  # normal latency probe (e.g. 4KB × 10)
PROBE_TYPE_BANDWIDTH     = 3   # bandwidth probe (e.g. 128MB)
PROBE_TYPE_CONFIRMATION  = 4   # confirmation probe during failure-aware mode
```

### 4.2 Reason codes

```python
REASON_SAFE              = 0   # window is safe, probe allowed
REASON_LOW_CONFIDENCE    = 1   # confidence below eta
REASON_GAP_TOO_SHORT     = 2   # g_lower_bound <= T_probe + margin
REASON_NO_DATA           = 3   # insufficient history for prediction
REASON_DRIFT_DETECTED    = 4   # workload drift, conservative mode
REASON_LOW_DATA_QUALITY  = 5   # high drop rate / unknown paths
REASON_COOLDOWN          = 6   # too soon since last probe (budget)
```

## 5. Probe Result Format

Output from prober to analyzer.

```csv
probe_id,path_id,probe_type,probe_size,start_ns,end_ns,latency_us,bw_gbps,overlap_flag,actual_gap_ns
```

| Column | Description |
|---|---|
| probe_id | Unique probe identifier (loop count) |
| path_id | Target path |
| probe_type | 1=tiny, 2=normal_latency, 3=bandwidth |
| probe_size | Bytes transferred |
| start_ns | Actual probe start (monotonic) |
| end_ns | Actual probe end (monotonic) |
| latency_us | Measured latency |
| bw_gbps | Measured bandwidth |
| overlap_flag | 1 if probe overlapped with business traffic |
| actual_gap_ns | Observed idle duration (retrospective) |

## 6. Analyzer Feedback Format

Output from analyzer back to predictor for online calibration.

```python
@dataclass
class Feedback:
    path_id: int
    predicted_window_start: int   # ns
    predicted_g_lower: int        # ns
    actual_idle_duration: int     # ns (retrospective)
    overlap_flag: bool            # true if probe overlapped with memcpy
    probe_type: int
    probe_duration: int           # actual probe latency in ns
    measured_latency_us: float
    measured_bandwidth_gbps: float
    prediction_error: int         # predicted_g_lower - actual_idle (negative = overestimation)
    workload_slowdown_hint: float # optional, if available
```

SCHEMA_VERSION = 1  # increment on breaking changes
