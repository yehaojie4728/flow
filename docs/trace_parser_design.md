# Trace Parser — Design Document

Generated by `docs/prompts/04_codex_trace_parser_generation.md`.

## 1. Purpose

The trace parser is the first processing stage in the FlowGap offline pipeline. It takes raw CSV trace files (from synthetic generation or eBPF collection) and produces normalized, sorted, per-path busy-idle timelines with probe-aware interval merging.

---

## 2. Architecture

```text
Raw CSV (HostDiagV2 or FlowGap format)
        │
        ▼
  parse_trace.py  ─── format detection, column mapping, normalization
        │
        ▼
  FlowEvent[]     ─── sorted, validated event list
        │
        ▼
  intervalize.py  ─── probe-aware micro-gap merging, gap extraction
        │
        ▼
  BusyInterval[] + Gap[]   ─── per-path busy-idle timeline
        │
        ▼
  Export: agg CSV, gap CSV, gap statistics
```

## 3. Design decisions

### 3.1 Backward compatibility with HostDiagV2

The parser auto-detects input format by scanning the CSV header:

| Header feature | Format |
|---|---|
| `source` + `destination` columns | HostDiagV2 (legacy, 11 cols) |
| `quality_flags` column | FlowGap (extended, 21 cols) |
| `size_mb` + `start_ns` (bare minimum) | HostDiagV2 |

HostDiagV2's string-based `Source`/`Destination` (`"Host(NUMA 0)"`, `"NPU 2"`) are normalized to numeric `src_dev`/`dst_dev`/`src_numa`/`dst_numa`. Direction is inferred from the src/dst strings.

### 3.2 Synthetic trace labeling

All synthetic events have `quality_flags | QF_SYNTHETIC`. The `generate_synthetic_trace.py` script always sets this flag. The parser preserves it. This allows downstream code to filter out synthetic data before making claims about real hardware.

### 3.3 Probe-aware intervalization

Micro-gap merging threshold = `min_probe_duration_ns + safety_margin_ns`.

Default values: `min_probe_duration_ns = 50_000` (50 µs, tiny latency probe), `safety_margin_ns = 100_000` (100 µs).

Two consecutive intervals `[A_start, A_end]` and `[B_start, B_end]` are merged if `B_start - A_end < threshold`. The `event_count` field tracks how many raw events were merged.

This differs from HostDiagV2's approach which uses simple temporal overlap (two events overlap in time → merge). FlowGap uses a configurable gap threshold that depends on probe characteristics.

### 3.4 Per-path grouping

Events are grouped by `(src_dev, dst_dev, direction, src_numa, dst_numa)`. Each group forms an independent timeline. This enables:
- Per-path prediction (each path has different burst-gap patterns)
- Link-level refinement (when link_bitmap is available)
- Independent feature extraction per path

### 3.5 Overlap detection

The `calc_overlap` function checks if a probe's `[start_ns, end_ns]` intersects any busy interval. Returns both `(overlap_flag, idle_ns)` so the analyzer can measure how much of the probe was in a gap.

## 9. Data conventions

- **Timestamps**: monotonic nanoseconds (`start_ns`, `end_ns`). Wall clock stored separately.
- **Sizes**: bytes internally, MB in CSV for readability. Conversion is `size_mb * 1024 * 1024 = size`.
- **Directions**: integer enum (0=H2H, 1=H2D, 2=D2H, 3=D2D).
- **Quality flags**: bit field. Bit 7 (`QF_SYNTHETIC=128`) set for all synthetic events.
- **Sorting**: events are always sorted by `ts_enter_ns` ascending.

## 10. Synthetic trace parameters

The `generate_realistic_trace.py` generator produces traces that model GLM-6B finetuning workloads:

- 8 paths (1 dominant data-loader + 7 workers), weighted by activity
- Dense bursts (3-8 events, intra-burst gaps 200us-3ms)
- Long compute gaps (20-500ms between iterations)
- Realistic BW ranges: local NUMA (8-23 GB/s), cross-NUMA (0.6-10 GB/s)
- Memcpy sizes: 24-1040 MB (matching real workload)

For small test traces (200 events), use the `generate_synthetic_trace.py` script.

For realistic training workload traces, use:
```bash
python trace_parser/generate_realistic_trace.py --mode glm --iterations 500
```

## 11. Real Trace Validation (GLM-6B Finetuning, 8× Ascend 910B)

### Data source

Two complete training runs collected with eBPF tracing:

| Pass | Events | Duration | H2D | D2H | Dominant pattern |
|---|---|---|---|---|---|
| Pass 1 (train) | 170,556 | 5,994 s | 7,356 | 163,200 | 8× symmetric D2H (~20K ev each) |
| Pass 2 (val) | 171,376 | 6,014 s | 8,176 | 163,200 | Same structure |

### Key findings

1. **D2H-dominant workload.** GLM-6B finetuning produces 96% D2H traffic (model checkpoint saves, output tensor transfers back to host). This contradicts the initial assumption of H2D-dominant data loading.

2. **Burst-gap structure confirmed at scale.** After probe-aware intervalization (threshold=150µs), each dominant D2H path has ~20K busy intervals — each event effectively stands alone as a burst. Gap p50 ≈ 190 µs, showing consistent inter-burst spacing.

3. **Safe-window availability is excellent.** 100% of gaps on all major paths can accommodate a tiny latency probe (50 µs). 30% of gaps accommodate a full bandwidth probe (5 ms).

4. **Cross-pass consistency.** Pass 1 and Pass 2 show near-identical path structures and gap distributions, confirming predictable patterns suitable for training a predictor.

### Corrected limitations

- Real GLM-6B trace is 96% D2H, not 100% H2D as previously assumed from the 1054-event trace.
- D2H and D2D patterns are now characterized from real data (170K+ events per pass).

## 12. Known limitations

- Does not yet handle binary FlowEvent format (only CSV). Binary format will be added when eBPF module is implemented.
- HostDiagV2 parsing assumes all events are sync (`async_flag=0`). This is correct for HostDiagV2 which only hooks sync memcpy.
- Path ID is computed as `hash(path_key) & 0xFFFF` when not present in input.
- Real GLM-6B trace has only H2D direction — D2H and D2D patterns not yet characterized.
- Secondary paths in synthetic traces may be too sparse at low iteration counts. Use `--iterations 500+` for better coverage.
- **Real trace validated**: 1054 events from GLM-6B finetuning parsed successfully, confirming format compatibility.
